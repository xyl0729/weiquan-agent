# 统一、有依据的咨询回答实施计划

> 日期：2026-08-16
> 依据：[统一、有依据的咨询回答体验设计](../specs/2026-08-16-unified-grounded-consultation-answer-design.md)
> 状态：实施中

## 目标与发布边界

本次同时提高回答完整性与成功性：每个首问和追问都先结合有效上下文理解
当前消息；需要完整法律说明时，在同一个 30 秒 Provider 预算内执行第二次
有依据成文；任一模型调用失败时，后端仍使用当前消息、历史事实和本地已核验
资料返回针对性答复。

只发布 `weiquan-app`。不重建或替换 PostgreSQL，不执行完整部署脚本，不修改
独立音频服务，不让模型自行生成法条、金额、时效或正式结论。

## 1. 锁定轮次意图与阶段推进

**文件**

- 修改 `app/agent/models.py`
- 修改 `app/agent/progression.py`
- 修改 `tests/test_progression.py`
- 修改 `tests/test_providers.py`

**实施**

- 增加统一轮次意图，至少区分提问、补充事实、陈述诉求、已完成动作、继续、
  纠正和新纠纷。
- 允许陈述式诉求携带直接回答，不再把直接回答绑定到问号。
- 将 `stated_goal` 作为不自动推进阶段的独立结果。
- 未核验阶段只在明确完成、拒绝、不回复、投诉等信号出现时推进；单纯“继续”
  或表达希望保持当前阶段。
- 用户纠正此前事实时，允许显式撤回旧事实，后续上下文不再使用错误值。

**验证**

- “我希望商家重新发货”不会被解释为已经联系商家。
- “继续”不会伪造行为或默认 `+1`。
- “已经联系但商家拒绝”可以按明确信号推进。

## 2. 修正语义路由仲裁

**文件**

- 修改 `app/agent/routing.py`
- 修改 `tests/test_routing.py`

**实施**

- 将本地关键词匹配改为语义候选的佐证和冲突仲裁，不再因关键词零分无条件
  否决高置信 DeepSeek 候选。
- 明确文本强冲突时优先采用明确主题；弱冲突或无关键词时保留高置信候选。
- 低置信、未知候选和跨案信号继续进入安全的未核验路径。
- 不把未知问题默认映射到合同或消费者领域。

**验证**

- 同义表达能够命中正式场景。
- 明确相反主题不会被错误保留。
- 无可靠候选仍保持 `unknown`。

## 3. 建立只读依据包与法条分层

**文件**

- 修改 `app/agent/models.py`
- 新增 `app/agent/grounding.py`
- 修改 `app/agent/pipeline.py`
- 按需新增本地领域法条映射数据
- 修改 `tests/test_pipeline.py`
- 新增 `tests/test_grounding.py`

**实施**

- 建立不可变 `GroundingPacket`，只包含后端确认的当前意图、事实、诉求、阶段、
  动作、证据、限制、问题和允许引用的法条正文。
- A 层正式 Playbook 保留本案结论、金额、时效和本案适用法条。
- B 层仅从现有已核验法条库选择领域通用依据，标明仍需结合本案核对，不输出
  verdict、确定金额或时效。
- C 层在没有可靠依据时只提供事实化动作、证据和至多一个高价值问题，不猜法条。
- 依据包对第二次模型调用只读，输出引用必须是允许 ID 的子集。

**验证**

- B 层可以带已核验引用，但不能表现成正式结论。
- 未知主题不能硬挂消费者法或合同法。
- 模型无法新增或篡改法条、金额、时效和 verdict。

## 4. 实现最多两次的有依据成文

**文件**

- 修改 `app/providers/base.py`
- 修改 `app/providers/deepseek.py`
- 修改 `app/providers/fake.py`
- 修改 `app/agent/pipeline.py`
- 修改 `tests/test_providers.py`
- 修改 `tests/test_pipeline.py`
- 修改 `tests/test_bounded_execution.py`

**实施**

- 第一次调用负责理解当前轮次、解析上下文、提取事实、识别诉求和给出安全的
  初步直接回答。
- 对复杂问句、法律解释、多轮追问或第一次结果不完整的轮次，使用依据包执行
  第二次成文。
- 第二次结果必须逐项覆盖直接回应、当前动作、证据、法律边界和至多一个问题，
  且只能使用依据包内容。
- 每轮硬限制最多两次模型调用，禁止第三次；两次共享 30 秒总预算，不为第二次
  重新计时。
- 第二次失败、超时或输出不合法时，使用第一次有效结果和依据包确定性装配；
  第一次失败时使用本地上下文降级。
- 两次调用按一个咨询轮次结算额度，并分别记录内部阶段、耗时与失败类别。

**验证**

- 简单完整问题只调用一次。
- 复杂问题可以调用两次且没有第三次。
- 二次调用输入不含依据包之外的法条或结论。
- 任一次失败都能在浏览器保护时限内结束并返回有内容答复。

## 5. 统一回答装配与 API 契约

**文件**

- 修改 `app/agent/guidance.py`
- 修改 `app/agent/pipeline.py`
- 修改 `app/api/schemas.py`
- 修改 `app/history/service.py`
- 修改 `tests/test_guidance.py`
- 修改 `tests/test_api.py`
- 修改 `tests/test_history.py`

**实施**

- 第一段始终回应当前问题、事实或诉求，静态阶段模板只能作为兜底素材。
- 正常回答至少满足“直接回应 + 具体动作”，并补充证据、依据或一个高价值问题。
- 复杂正文上限提高到约 1200 个中文字符；压缩时优先保留答案、动作和安全边界。
- 每轮最多一个问题，避免重问已经确认的事实。
- 放宽 B 层引用的公开响应契约，同时禁止 B 层出现正式方案字段。
- 历史恢复保持同一契约，并兼容改动前已存储的回答。

**验证**

- 典型三轮对话每轮都有实质进展，不重放上一轮。
- Provider 故障不再只返回一个泛化澄清问题。
- API 和历史数据都能区分正式依据与一般法律依据。

## 7. 自动化、真实模型与发布验收

**验证顺序**

1. 路由、轮次意图、阶段推进和模型契约聚焦测试。
2. Pipeline、依据包、法条分层、失败降级和额度测试。
3. API、历史、JavaScript 契约与语法检查。
4. 不依赖外部服务的完整 pytest。
5. PostgreSQL 集成测试和生产记账、金额熔断检查。
6. 真实 DeepSeek 执行关键多轮对话，记录调用次数、总延迟和上下文关联。
7. 本地桌面与 `360x800` 手机浏览器验收。
8. `git diff --check`、敏感信息扫描和改动范围复核。

**发布**

- 重启本地服务并完成页面验收后，构建不可变应用镜像。
- 只替换 `weiquan-app`，保留生产环境文件和数据库容器。
- 线上验证健康检查、匿名试用、登录首问、上下文追问、B 层依据、降级、额度
  与静态文件版本。
- 若线上核心链路异常，只回滚本次应用镜像，不回滚用户数据。

## 完成标准

- 完整性：每轮直接回应当前消息，给出可执行动作；需要法律说明时有可靠依据和
  适用边界；复杂回答不因模板或长度限制丢失核心内容。
- 成功性：每轮至少尝试一次上下文理解，最多两次；超时、无效 JSON、二次失败、
  Playbook 未命中均能返回针对性答复，并正确处理额度。
- 正确性：诉求不当作完成事实，阶段不自动前进，未知领域不猜法条，模型不能
  改写后端确定的结论与引用。
- 发布：本地与线上核心多轮场景通过，线上只更新 `weiquan-app`，其他服务和数据
  不受影响。
