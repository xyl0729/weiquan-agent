# 咨询续问防重复实施计划

> 日期：2026-08-13
> 依据：[咨询续问防重复设计](../specs/2026-08-13-consultation-non-repetition-design.md)
> 状态：实施中

## 目标与边界

为正式 Playbook、未核验主题、紧急指导、事实收集和历史恢复建立统一的会话推进与
防重复规则。任何新轮次只有在包含新事实影响、新问题答案、新行动、新阶段、新追问、
新案件或风险变化时才能保存。

本次不修改 Playbook 法律结论，不调用真实 DeepSeek，不改变账号、额度、附件所有权
或 Provider 选择策略，不新增数据库表或字段，也不重写已有历史记录。

## 1. 历史内容投影与重复判定

**文件**

- 新增 `app/agent/progression.py`
- 新增 `tests/test_progression.py`

**实施**

- 定义只包含公开核心内容的 `VisibleTurnContent`、阶段和判定结果。
- 兼容投影方案、方案更新、短回复、事实问题、未核验指导、紧急指导和分案提示。
- 对中文与英文文本做 NFKC、大小写、空白、标点和列表编号归一化。
- 实现完全重复、近似文本、结构重复和重复追问检测。
- 将必要的风险提醒、限制说明和法条标签排除在“有效推进”之外。
- 对整段会话历史生成有界的内容单元和指纹，不记录用户原文。

**验证**

- 精确重复、换标点、换编号和轻度改写均被识别。
- 新事实、新动作、新阶段或更具体的问题不会被误拦截。
- 旧版与缺失字段的响应可安全投影。

## 2. 确定性会话推进

**文件**

- 修改 `app/agent/guidance.py`
- 修改 `app/agent/continuation.py`
- 修改 `app/agent/models.py`
- 修改 `app/providers/fake.py`
- 修改 `tests/test_guidance.py`
- 修改 `tests/test_pipeline.py`

**实施**

- 识别“继续”“然后呢”等无新信息推进语句。
- 正式案件从已有行动及历史引用中选择尚未服务的下一项，不调用 Provider。
- 未核验主题按安全、证据、首次联系、等待、催办、升级、专业协助七个阶段推进。
- 从历史覆盖记录恢复未核验主题，从历史核心内容推导已完成阶段。
- 对“已发送”“未回复”“拒绝处理”“已投诉”等状态跳转到正确后续阶段。
- 事实收集每轮只问一个未问过的必填事实；再次询问时必须更具体。
- 重复紧急风险只保留一句安全提醒，并询问新的风险状态；风险解除后恢复原案件。

**验证**

- 连续“继续”逐步推进，耗尽后不再生成换句话答案。
- 15 个未核验主题共享阶段规则且保持主题专属内容。
- 9 个正式主题的下一行动不会重复。
- 事实问题和紧急模板不会连续重复。

## 3. 管线统一守门与确定性修复

**文件**

- 修改 `app/agent/pipeline.py`
- 修改 `app/agent/errors.py`
- 修改 `app/api/schemas.py`
- 修改 `tests/test_api.py`
- 修改 `tests/test_pipeline.py`

**实施**

- 所有候选响应在持久化前进入同一防重复守门器。
- Provider 返回重复答案时不重试模型，改成本地下一行动、事实影响、精准问题或当前卡点。
- 有新事实但完整方案不变时返回简短事实影响，不再展示同一整套方案。
- 完整方案确有变化时保留最新规范方案，同时附带只描述变化的短回复。
- 无剩余动作、问题或风险变化时抛出安全的 `case_no_progress`，不创建轮次。
- 在 Provider 配额预留前拦截可确定的无进展“继续”。

**验证**

- Fake Provider 故意返回上一轮答案时，最终结果仍有实质推进。
- 修复过程不触发第二次 Provider 调用。
- 无进展响应返回 `409` 且不写入消息、用量或附件绑定。

## 4. 原子持久化与并发保护

**文件**

- 修改 `app/db/contracts.py`
- 修改 `app/db/session.py`
- 修改 `app/db/postgres.py`
- 修改 `app/db/models.py`（仅在需要新增非持久化命令模型时）
- 修改 `tests/test_db.py`
- 修改 `tests/integration/test_postgres_store.py`
- 新增或修改并发集成测试

**实施**

- 持久化命令携带分析时看到的最新轮次 ID 和候选比较内容。
- SQLite 在序列化写事务内、PostgreSQL 在锁定 session 行后核对最新轮次。
- 并发等价请求最多保存一条；并发但不同的陈旧请求返回可重试冲突。
- 冲突时不更新 session、不插入 turn、不绑定附件。

**验证**

- SQLite 与 PostgreSQL 都能阻止等价第二次写入。
- 并发失败不会产生部分提交。
- 旧调用方在没有历史轮次时仍能正常首次提交。

**文件**

- 修改 `app/web/js/api.js`
- 修改 `app/web/js/app.js`

- 修改 `tests/test_history.py`
- 修改 `tests/test_web_security.py`

**实施**

- 允许 `plan_update` 同时携带完整方案和简短更新说明。
- 方案更新先显示变化摘要，完整方案默认折叠；旧历史仍按原格式显示。
- 未核验后续阶段使用短回复展示，不重复完整指导卡。
- `case_no_progress` 不追加用户或助手气泡，保留输入内容并定位既有答案。
- 会话轮次只按已持久化 turn 编号。

**验证**

- 新旧方案更新记录均可恢复和渲染。
- 无进展冲突不会制造假轮次。
- 桌面与移动视口内容不重叠，折叠控件可键盘操作。

## 完成标准

- 同一咨询中的后续可见核心内容不存在无实质变化的重复。
- 补充新事实时不再重新展示上一轮整套答案。
- 连续“继续”按阶段前进，动作耗尽后不写入新轮次。
- 所有现有咨询、账号、额度、附件、历史和部署契约测试保持通过。
