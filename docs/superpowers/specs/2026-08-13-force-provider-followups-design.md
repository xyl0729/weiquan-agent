# 追问强制调用 Provider 设计

## 状态

已根据 2026-08-13 的确认进入实施。

## 目标

已有咨询会话的每一次追问都先发起且只发起一次当前配置
Provider（生产环境为 DeepSeek）请求，然后再执行现有的本地案件推进
规则。这样“继续”“下一步”“对方拒绝处理”和紧急状态恢复等追问
都会显示真实的请求 ID、Token 用量和费用信息。

## 范围

纳入强制调用的路径：

- 已有正式案件方案时的案件续问；
- 已有未核验主题时的阶段推进或状态更新；
- 已有会话中的重复紧急风险报告；
- 紧急插曲解除后的正式案件恢复或未核验阶段恢复；
- 其他已有会话的普通追问（原本已经调用 Provider）。

首次提交、没有历史轮次的紧急求助仍由本地安全规则直接处理。它不是
追问，且本地安全指导必须在模型不可用时也能工作。

## 数据流

1. 会话、历史轮次、附件证据和当前 Provider 先完成既有校验。
2. 需要本地确定性推进的追问先调用一次对应接口：
   - 正式案件使用 `continue_case`；
   - 未核验和紧急路径使用 `extract_facts`。
3. 校验 Provider 身份并应用已有用量控制；不使用模型返回内容改变本地
   阶段、风险和已锁定案件规则。
4. 本地规则生成最终响应，但使用本次调用的 Provider 元数据。
5. 持久化前继续使用已有的重复检测和并发检查，不因强制调用而重试模型。

## 错误和费用

- Provider 请求失败或返回非法结构时，沿用现有安全错误处理，不伪造成功
  的请求 ID 或 Token 用量。
- 成功返回但被本地重复检测拒绝时，不进行第二次 Provider 请求。
- 每个追问最多预留和结算一次 Provider 配额；失败请求按现有控制器逻辑
  退款，成功持久化的请求正常结算。

## 验证

使用 Fake Provider 验证：

- 正式案件的“继续”先调用一次 `continue_case`，再推进下一行动；
- 未核验主题的状态更新先调用一次 `extract_facts`，并保留阶段跳转；
- 重复紧急报告和解除紧急状态各调用一次；
- 本地初次紧急求助仍不调用 Provider；
- 普通追问和初次咨询的既有调用次数、结果和配额行为不回归。
