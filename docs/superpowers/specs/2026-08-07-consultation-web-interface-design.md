# 维权咨询 Web 界面设计

## 文档状态

- 日期：2026-08-07
- 版本：v1
- 状态：分段设计已获用户确认，待用户复核书面规格
- 项目目录：`D:\agent development\weiquan-agent`
- 视觉参考：`D:\agent development\consultation-layout-casefile-white-v4.html`

本文档定义现有维权 Agent 的首个可用 Web 界面。它覆盖本机文字咨询、会话历史、案件工作台、错误处理和浏览器验收，不改变既有法律数据、Playbook 规则或 DeepSeek 安全边界。

## 1. 目标与成功标准

本阶段把已有的 `POST /api/consult` 从命令行接口变成可供用户本人在本机完整试用的咨询界面。

成功标准：

1. 用户打开首页后，可以直接描述纠纷或使用三个常见入口填写示例问题。
2. 首次成功发送后，页面进入案件工作台，并按后端状态继续追问或展示方案。
3. 每条新咨询拥有独立 `session_id`，不同案件的上下文不会混合。
4. 用户可以在默认 72 小时留存期内重新打开本机历史并继续咨询。
5. 案件摘要、证据和法律依据全部来自现有结构化响应，不由前端推断或再次调用模型生成。
6. DeepSeek Key 不进入浏览器资源、请求体、响应、日志或 SQLite。
7. 页面在桌面和 360px 宽手机上无横向溢出、文本裁切或控件重叠。

## 2. 本阶段范围

本阶段包含：

- FastAPI 同源托管的 Web 页面和本地静态资源。
- 纯文字咨询，不支持附件。
- 初次进入状态和咨询进行中状态。
- 本机咨询历史的列表、恢复和删除。
- `need_more_facts`、`ready`、`escalate` 三种业务状态。
- 加载、空状态、输入错误、会话过期、限流、服务异常和数据完整性错误。
- Fake Provider 自动化测试和一组受控 DeepSeek 真实联调。

本阶段不包含：

- 文件上传、OCR 或文档解析。
- 联网搜索、自动抓取或模型生成法条。
- 对外分享页或公开链接。
- 账号、登录、跨设备同步或长期云端归档。
- 不同案件自动共享上下文或自动合并。
- 邮件、短信、桌面通知或支付。

## 3. 体验与视觉方向

视觉基线采用已确认的白色案件档案方向：

- 主界面为白色，侧栏使用浅冷灰。
- 正文使用近黑色，档案蓝、朱红和标记黄仅表达操作或状态。
- 参考色为白色 `#ffffff`、画布灰 `#f5f6f4`、正文 `#202421`、档案蓝 `#315f70`、朱红 `#aa493d` 和标记黄 `#c39d36`。
- 不使用渐变、发光、装饰光斑、营销式大标题或大量工具按钮。
- 以分隔线、留白和稳定网格组织信息，不把页面区段包装成层层嵌套的卡片。
- 字体使用本机中文系统字体栈，字距固定为 `0`，不依赖外部字体服务。
- 图标使用本地 Lucide 资源，不依赖 CDN；陌生图标提供可访问名称或悬停提示。
- 卡片和输入控件圆角不超过 8px。

视觉稿中的“初次进入 / 咨询进行中”预览切换器、演示案件和硬编码状态不进入正式页面。正式状态只由 API 和页面状态驱动。

## 4. 页面结构与交互

### 4.1 初次进入

桌面端显示左侧咨询记录和中央新咨询区，不显示右侧案件摘要。

中央区域包含：

- 标题“先把事情说清楚”和一段简短引导。
- 多行文字输入框。
- 发送按钮和“本机测试”提示。
- 三个常见咨询入口：
  - 消费纠纷：商品与描述不符。
  - 房屋租赁：押金被无故扣除。
  - 劳动权益：工资长期拖欠。

点击常见入口只把示例文字填入输入框，用户可以继续修改；它不会自动发送，也不会预先锁定场景。

左侧区域包含：

- “新咨询”命令。
- 最近咨询，按 `updated_at` 倒序。
- 每项显示确定性标题、更新时间和业务状态。
- “仅保存在本机”提示。

历史标题由第一条用户消息去除多余空白后生成，最多保留 24 个 Unicode 字符，超出时追加省略号；该过程不调用模型。

### 4.2 首次发送

发送前执行空白和长度校验。请求进行中时：

- 保留输入内容。
- 锁定当前发送按钮，防止重复提交。
- 显示明确的处理中状态。

首次请求不传 `session_id`。只有收到成功响应后，前端才记录返回的 `session_id`、清空输入框并进入案件工作台。请求失败时保留在当前页面并保留草稿。

### 4.3 案件工作台

桌面端采用三栏结构：

- 左栏：咨询历史与新咨询。
- 中栏：当前案件标题、状态、对话线程和输入框。
- 右栏：案件摘要。

中栏按时间顺序展示用户消息和 Agent 响应：

- `need_more_facts`：显示后端返回的 `questions`，继续接受文字回答。
- `ready`：显示方案摘要、证据清单、行动步骤、沟通话术、时效和限制。
- `escalate`：保留已有安全信息，并突出需要专业人员核对的原因，不营造确定结论。

法律引用显示法律名称和条号，展开后可阅读原文；来源链接只使用后端已校验的 `source_url`。

### 4.4 案件摘要

右栏固定为四个信息区：

1. 案情事实：咨询完成前按用户各轮陈述显示简短片段；完成后优先显示 `plan.summary` 和 `verdict.key_point`。
2. 待补充：显示最新一轮 `questions`；无待补充项时显示完成状态。
3. 证据：显示 `plan.evidence_now`。
4. 法律依据：显示 `citations`，包括法律名称、条号和来源。

前端不得显示内部英文槽位名或枚举值，不得根据原始 `facts` 自行翻译或生成法律结论。没有对应后端字段时，该区显示中性空状态，不编造占位内容。

### 4.5 历史恢复与删除

点击历史项后读取该会话详情并重建对话与案件摘要。未过期会话继续使用原 `session_id`。

删除操作必须二次确认。确认后删除会话及关联 turns 和审计记录，并立即从列表移除。若删除的是当前会话，页面返回新咨询状态。

“新咨询”始终清空当前页面状态并在下一次发送时创建新 `session_id`，不会复用当前案件事实。

## 5. 技术架构

### 5.1 前端交付

项目继续以 FastAPI 为唯一应用服务，不增加独立 Node 服务或前端构建链。建议文件边界：

- `app/web/index.html`：语义化页面骨架。
- `app/web/styles.css`：设计令牌、布局、状态和响应式规则。
- `app/web/js/api.js`：`fetch`、响应校验和安全错误归一化。
- `app/web/js/state.js`：当前会话、历史、草稿和请求状态。
- `app/web/js/render.js`：页面各状态的 DOM 渲染。
- `app/web/js/app.js`：事件绑定和页面启动。
- `app/web/icons/`：本地使用的少量 Lucide 图标。

模块保持窄职责。API 客户端不知道页面结构，渲染层不直接访问 `fetch`，状态层不生成法律结论。

FastAPI 提供：

- `GET /`：正式咨询页面。
- `/static/*`：同源静态资源。
- 现有 `/health` 和 `/api/*`：保持 API 边界。

同源托管避免额外 CORS 配置。页面不读取 `.env`，也不提供填写模型 Key 的控件。

### 5.2 后端历史边界

现有 `SessionStore` 已保存 sessions、turns 和响应 JSON，但缺少供界面使用的列表、详情和删除方法。本阶段只扩展读取与删除边界，不改变 Agent Pipeline 的决策流程。

建议增加独立的历史服务或等价窄模块，负责：

- 调用 `SessionStore` 列出未过期会话。
- 读取单个会话及其 turns。
- 生成不调用模型的历史标题。
- 删除会话并依靠外键级联删除关联数据。
- 把数据库记录转换为公开 API schema。

历史服务不执行检索、规则求值或 Provider 调用。`POST /api/consult` 继续由现有 `ConsultationPipeline` 处理。

## 6. API 契约

### 6.1 咨询

继续使用现有接口：

`POST /api/consult`

```json
{
  "session_id": null,
  "message": "商家发错货，但拒绝退款",
  "jurisdiction": null
}
```

后续轮次把成功响应中的 `session_id` 原样带回。前端只使用公开响应中的状态、问题、方案、引用和非敏感元数据。

### 6.2 历史列表

`GET /api/sessions`

```json
{
  "sessions": [
    {
      "session_id": "uuid",
      "title": "商家发错货，但拒绝退款",
      "scenario_id": "return_refused",
      "status": "need_more_facts",
      "created_at": "2026-08-07T00:00:00Z",
      "updated_at": "2026-08-07T00:01:00Z",
      "expires_at": "2026-08-10T00:01:00Z"
    }
  ]
}
```

要求：

- 返回前先清理过期会话。
- 只返回至少包含一个成功持久化 turn 的会话；首次请求失败留下的零 turn 会话不进入历史。
- 按 `updated_at` 倒序。
- 标题来自第一条用户消息，按 24 个 Unicode 字符的固定规则截断。
- 不返回 facts、完整响应、审计记录、Prompt、请求头或 Key。

### 6.3 历史详情

`GET /api/sessions/{session_id}`

```json
{
  "session": {
    "session_id": "uuid",
    "title": "商家发错货，但拒绝退款",
    "scenario_id": "return_refused",
    "status": "ready",
    "created_at": "2026-08-07T00:00:00Z",
    "updated_at": "2026-08-07T00:03:00Z",
    "expires_at": "2026-08-10T00:03:00Z"
  },
  "turns": [
    {
      "turn_id": "uuid",
      "user_message": "商家发错货，但拒绝退款",
      "response": {
        "session_id": "uuid",
        "turn_id": "uuid",
        "audit_id": "uuid",
        "followup_round": 1,
        "can_ask_more": true,
        "status": "need_more_facts",
        "verdict": null,
        "plan": null,
        "questions": ["平台是否已经给出售后处理结论？"],
        "limitations": [],
        "citations": [],
        "usage": {
          "provider": "deepseek",
          "model": "deepseek-chat",
          "request_id": null,
          "input_tokens": 100,
          "output_tokens": 20,
          "total_tokens": 120,
          "estimated_cost_usd": null
        }
      },
      "created_at": "2026-08-07T00:00:00Z"
    }
  ]
}
```

`response` 使用保存时已经通过 `ConsultResponse` 校验的公开结构，并在读取时再次通过同一公开 schema 校验。详情接口不返回内部审计事件、规则输入快照或 Provider 原始内容。

无效、未知或已过期会话使用安全的 `session_not_found` 错误，不返回数据库细节。

### 6.4 删除

`DELETE /api/sessions/{session_id}`

成功返回 `204 No Content`。删除必须覆盖 session、turns 和关联审计记录。对已经不存在的会话保持幂等，不返回敏感差异信息。

## 7. 页面数据流

1. 页面启动并行请求 `/health` 和 `/api/sessions`。
2. 历史为空时显示新咨询；历史读取失败时仍允许新咨询，但显示可重试提示。
3. 用户发送第一条消息，前端调用 `/api/consult`，不传 `session_id`。
4. 成功响应建立当前会话，并把它加入历史列表。
5. `need_more_facts` 响应把问题加入对话和“待补充”区。
6. 后续回答携带当前 `session_id`，后端合并事实并继续既有 Pipeline。
7. `ready` 或 `escalate` 响应展开完整方案、证据和法律依据。
8. 点击历史项时调用详情接口，按 turns 重建中栏和右栏。
9. 刷新页面后可从历史重新进入；`sessionStorage` 最多保存当前会话 ID 和非敏感界面偏好，不复制完整消息。
10. 新咨询只重置前端活动状态，直到首次成功发送才由后端创建新记录。

## 8. 留存、隐私与安全

- 会话继续使用 `SESSION_TTL_HOURS`，默认 72 小时。
- 每次成功更新会话时沿用现有滑动过期机制。
- 过期清理删除 session，并通过外键级联删除 turns 和审计记录。
- 浏览器不使用 `localStorage` 或 IndexedDB 长期复制完整咨询内容。
- 用户输入使用 DOM `textContent` 或等价安全 API 渲染，不拼接进 `innerHTML`。
- 法律来源链接仅接受后端 Pydantic 已校验的 HTTP(S) URL，并使用安全的新窗口属性。
- 页面、错误消息和浏览器日志不得出现 API Key、Authorization Header、完整 Prompt、堆栈或本地数据库路径。
- 本机测试服务只监听 `127.0.0.1`，不默认暴露到局域网或公网。
- 页面不使用内联事件处理器，并发送仅允许同源脚本、样式和接口连接的 Content Security Policy。
- DeepSeek 仍是本阶段唯一真实测试模型；Fake Provider 只用于离线自动化测试。
- 不因 DeepSeek 请求失败而静默切换到 Fake Provider。

## 9. 错误与状态设计

### 9.1 客户端输入

- 空白输入：在输入框附近显示提示，不发送请求。
- 超长输入：显示当前限制并保留草稿。
- 请求进行中：锁定当前发送动作，防止双击重复提交。

### 9.2 业务和服务错误

- `need_more_facts`：正常咨询状态，不使用错误样式。
- `session_not_found`：说明会话不存在或已过期，将当前内容转为只读，并提供“开始新咨询”。
- `429`：说明当日调用额度已达到限制，保留未发送内容。
- `503` 或网络中断：显示暂时不可用和重试操作，保留草稿。
- `500` 数据完整性错误：停止展示本次未完成的法律结果，不渲染部分方案。
- 历史读取失败：历史区显示局部重试，不阻断新咨询。

前端根据稳定错误 `code` 选择文案，未知错误使用统一安全提示。原始响应文本、异常对象和 traceback 不直接显示。

## 10. 响应式与可访问性

- 宽屏显示历史、对话和摘要三栏，中央对话保持主要宽度。
- 中等宽度优先隐藏固定历史栏，保留对话与窄摘要。
- 手机端使用单列顺序：案件标题、对话、输入、案件摘要。
- 手机端历史通过明确的菜单或抽屉打开，不占用固定屏幕宽度。
- 固定工具栏、发送按钮和状态标记使用稳定尺寸，加载状态不得造成布局跳动。
- 文字允许自然换行，最长单词或 URL 不得撑破容器。
- 键盘焦点清晰可见；图标按钮具有 `aria-label`。
- `Enter` 发送，`Shift+Enter` 换行；输入法组合期间不得误发送。
- 状态不能只依赖颜色，必须同时提供文字或图标。
- 遵守 `prefers-reduced-motion`，不使用无功能目的的动画。

## 11. 测试设计

### 11.1 后端自动化

在现有 pytest 基线上增加：

- SessionStore 列表排序、详情恢复、删除级联和过期过滤。
- 历史标题的空白归一化、固定截断和 Unicode 文本。
- 零 turn 会话不进入历史列表。
- 历史列表、详情、删除的 API schema 和安全错误。
- 不同 session 的 turns 不串联。
- 历史 API 不返回 Key、Prompt、审计细节或内部 facts。
- 新接口不改变现有 `/api/consult`、`/health`、限流和熔断行为。

默认自动化测试使用 Fake Provider，禁止访问 DeepSeek 网络。

### 11.2 浏览器验收

使用本地服务和确定性 Fake Provider 覆盖：

- 空历史初始页。
- 三个常见入口填充但不自动发送。
- 首次发送进入工作台。
- 追问、完成方案和升级状态。
- 新建独立咨询、历史切换、刷新恢复和删除。
- 空白、超长、重复点击、过期、429、503、500 和断网状态。
- 法律引用展开及来源链接。
- 长中文、长 URL、长历史标题和多轮内容。

至少检查 1366×768、736×900、390×844 和 360×800。验收无横向滚动、文本裁切、不可达控件或重叠，并保存桌面与手机关键状态截图供人工复核。

### 11.3 DeepSeek 真实联调

真实联调不进入默认 pytest。它只使用项目根目录 `.env` 中的 DeepSeek 配置，执行一组受控的“租房押金扣减”两轮咨询：

1. 首轮触发 `need_more_facts`。
2. 次轮补充事实并得到 `ready` 或合理的 `escalate`。
3. 检查结构化字段、法律引用、Token 用量和历史恢复。
4. 检查浏览器、API 响应、日志和 SQLite 中没有 Key。

## 12. 验收清单

- 首页第一屏就是可使用的咨询界面，不是营销落地页。
- 初始状态有历史、输入和三个入口，没有空的案件摘要栏。
- 第一次成功发送后进入案件工作台。
- 每次新咨询创建独立会话。
- 72 小时内的历史可以恢复和继续，过期记录自动删除。
- 右栏只重排后端字段，不额外调用模型。
- 文件上传、联网搜索和分享没有出现在本阶段界面或 API。
- DeepSeek Key 只存在于未跟踪的 `.env` 或受控环境变量中。
- 所有现有测试和新增测试通过。
- 桌面及手机浏览器验收通过。

## 13. 后续升级边界

本阶段只保留清晰模块边界，不预先实现未使用功能。

建议后续顺序：

1. 文件上传与 OCR：作为独立附件资源接入，提取结果经过安全校验后再进入咨询上下文。
2. 安全分享：增加可撤销、可过期、可脱敏的只读分享令牌。
3. 权威联网检索：只接入明确的官方来源，并保留来源、抓取时间和校验状态。
4. 跨设备案件管理：把历史仓储从本机范围升级到带账号作用域的存储。

升级案件管理时，默认继续保持每个案件上下文隔离。只有用户明确选择时才能合并相关咨询，并记录合并来源，避免不同纠纷的事实互相污染。
