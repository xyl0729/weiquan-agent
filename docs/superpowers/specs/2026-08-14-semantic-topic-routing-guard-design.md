# 通用主题语义路由保护设计

## 背景

当前候选主题主要由模型返回。即使原文只出现了金额、联系不上或删除好友等通用
信息，模型也可能把其他纠纷误判为“转账支付与网络诈骗”。主题一旦错误，后续
指导会沿错误方向继续，造成回答没有理解用户核心事实的感受。

本次修复不能只匹配某一段对话，而应为所有咨询增加统一的候选主题校验，并补齐
游戏账号借用、违规使用和封禁损失这一已有覆盖空白。

## 目标

- 模型候选主题必须与当前用户原话存在主题特有的语义依据。
- 金额、转账记录、联系不上等通用事实不能单独触发诈骗主题。
- 无法确认主题时安全降级为未核验长尾问题，不生成武断结论。
- 支持游戏账号借用、开挂封禁、充值损失和平台申诉类纠纷。
- 保持每次非首次紧急求助追问都会调用配置的生产 DeepSeek。
- 不改变正式 Playbook 的法律规则、数据库结构和生产密钥管理方式。

## 方案选择

### 采用：本地确定性语义闸门

每个主题在已有展示别名之外，维护用于验证候选结果的主题特有信号。路由器收到
模型候选后，检查原文是否命中该候选的信号；不一致时先尝试原文可明确识别的未
核验主题，否则降级为 `unknown`。

优点是行为可测试、无额外模型费用、延迟稳定，并且能覆盖所有主题。缺点是新增
主题时需要同时维护少量信号词。

### 不采用：只为诈骗增加黑名单

改动较小，但只能修复当前误判，其他主题之间仍可能出现同类问题。

### 不采用：每轮增加第二次模型复核

语义更灵活，但会增加费用、延迟和服务失败面，而且第二个模型判断仍需本地边界
保护。

## 设计

### 主题注册

`TopicDefinition` 增加内部路由信号。Provider 仍只看到主题标签、描述性别名和
覆盖模式，不获得修改覆盖权限。新增未核验主题 `game_account_dispute`，涵盖：

- 游戏账号、借号或共享账号；
- 他人开挂、作弊或违规使用；
- 账号封禁、处罚申诉；
- 游戏充值、道具或账号使用价值受损。

### 候选主题校验

`ScenarioRouter.route()` 按以下顺序处理：

1. 本地安全信号继续优先于普通主题。
2. 置信度低于阈值的候选不被采用。
3. 模型候选必须命中候选主题的本地语义信号。
4. 候选不一致时，仅从原文明确命中的未核验主题中回退。
5. 仍无法确认时返回 `unknown`。

正式 Playbook 同样要求原文具有对应主题信号，避免高置信度错误候选直接进入正式
法律流程。已有会话绑定正式 Playbook 后的同案续问不受影响，因为它使用独立的
续问流程和既有案件上下文。

诈骗主题采用更严格的肯定信号，只接受明确的被骗转账、冒充身份、盗刷、刷单等
表达。单独出现金额、充值、付款、转账记录、联系不上或删除好友，不构成诈骗
主题依据。

### 指导内容

游戏账号纠纷使用专用未核验指导：

- 优先修改密码、关闭共享登录并保护验证码；
- 向游戏平台申诉封禁，索取处罚依据、登录和违规记录；
- 保存账号信息、借号约定、聊天、充值、登录及封禁通知；
- 起诉问题只提示核对对方身份、借用约定、可证明损失和因果关系，不承诺责任或
  胜诉结果。

### DeepSeek 提示

候选主题提示明确要求依据“核心行为和争议对象”分类，不得仅凭金额或失联判断为
诈骗；证据不足时返回 `unknown`。这用于提升模型首选质量，本地语义闸门仍是最终
边界。

## 错误处理

- 模型返回未知 ID、低置信度或语义不一致候选时，安全降级而不是报错。
- Provider 输出结构无效时保留现有降级策略。
- 明确紧急安全信号继续走紧急指导，不被普通主题校验阻断。
- 不把用户正文、密钥或模型提示写入生产日志。

## 测试

新增并更新以下覆盖：

- 游戏账号借用后开挂封禁可识别为 `game_account_dispute`。
- 第二轮出现“4000 元、联系不上、删除”仍不会改判诈骗。
- 明确冒充客服骗转账仍识别为 `payment_fraud`。
- 借款、租赁、劳动、服务和账号充值等带金额场景不会误判诈骗。
- 高置信度但与原文无关的正式和未核验候选都会降级或回退。
- 所有注册主题均有可识别样例和可构建指导。
- 相关测试、全量测试、编译检查和 `git diff --check` 全部通过。

## 发布

测试通过后使用固定镜像标签 `weiquan-agent:2026.08.14-1`，在生产服务器执行
`IMAGE_SOURCE=build` 的标准预检和部署脚本。发布过程保留
`/etc/weiquan/weiquan.env`，先备份数据库，不重建 PostgreSQL，只更新应用容器。

发布后检查 `/live`、`/ready`、`/internal/metrics`、容器状态和公网 HTTPS。最后
使用不含个人敏感信息的等价测试对话验证线上主题路由；真实 DeepSeek 请求只进行
必要的一次端到端验证。
