# 咨询回复韧性与延迟设计

## 状态

- 日期：2026-08-15
- 范围：匿名试用和登录用户的咨询、追问、前端响应校验与配额结算
- 发布对象：仅 `weiquan-app`

## 背景

线上匿名试用曾在后端返回 `200` 后，由浏览器显示“服务返回的数据未通过完整性
检查”。本地代码、线上容器中的 `api.js` 哈希一致，因此该问题不是漏部署，而是
前后端响应契约不一致：

- 后端允许安全澄清响应使用
  `turn_kind="fact_collection"` 与
  `coverage.mode="unverified_guidance"`；
- 前端 `validateTurnCombination()` 把所有非正式覆盖的事实收集响应都判为非法；
- Provider 输出异常时，后端正好会返回上述合法组合，因此浏览器拒绝展示。

同一线上请求耗时约 75.8 秒。DeepSeek 单次 HTTP 请求允许等待 30 秒，网络层可
重试一次，结构化输出失败后还可再发起一次格式纠正请求。这些等待当前可以叠加，
导致用户长时间看到加载状态。

线上只读核验还确认，该次匿名试用配额预留最终为 `refunded`：预留创建于
`2026-08-14 18:41:12 UTC`，退回于 `18:42:28 UTC`。因此配额退款逻辑已经生效，
但页面没有成功展示后端的安全回复。

## 目标

- 每次咨询和追问立即调用配置的 DeepSeek，并携带当前问题及最近有效会话上下文。
- DeepSeek 整次逻辑调用的总预算为 30 秒，网络重试和格式纠正共享该预算。
- 合法 DeepSeek 结果一旦返回就立即展示，不增加人为等待。
- DeepSeek 超时、网络错误、繁忙或输出异常时，返回与当前纠纷和已有上下文有关的
  本地安全回复。
- 浏览器的咨询等待上限为 35 秒，超时后必须结束加载状态，不能无限转圈。
- Provider 降级回复不消耗匿名试用或登录用户额度。
- 前后端对响应组合采用相同契约，且只放行后端明确允许的安全例外。

## 非目标

- 不修改 Playbook 法律规则、法条库、数据库结构或配额上限。
- 不把 DeepSeek 故障静默切换为 Fake Provider。
- 不扩大前端对其他非法响应组合的接受范围。
- 不改注册、验证码、邮件、附件等无关流程。
- 不重启或重建 PostgreSQL。
- 不触碰本项目以外的服务器服务。

## 方案选择

### 采用：端到端时间预算与确定性本地降级

在 DeepSeek Provider 外层设置一次 30 秒总预算，把队列等待、HTTP 重试和结构化
格式纠正全部包在同一预算内。Pipeline 对 Provider 故障统一生成基于本地规则和
会话状态的安全回复；前端同步后端契约并增加 35 秒等待保护。

该方案同时解决延迟叠加、异常无回复、上下文丢失和前端误拒绝，且不降低正常
DeepSeek 路径的回答质量。

### 不采用：仅关闭 DeepSeek 重试

这能降低最坏延迟，但首次请求仍可等待 30 秒，格式异常仍会直接暴露为错误，也
不能修复浏览器错误拒绝合法响应的问题。

### 不采用：只延长浏览器等待时间

这会掩盖后端等待叠加，让用户等待更久，并且不会改善 Provider 故障时的回复质量。

## 核心不变量

- 当前用户消息始终是本轮最高优先级输入，历史上下文只用于解释指代和延续同一
  纠纷，不能覆盖当前明确表达。
- 已绑定正式 Playbook 或已有未核验主题时，Provider 故障不得主观切换纠纷类型。
- 本地降级不得编造事实、法条、责任结论、时效结论或胜诉预测。
- 未通过 Provider 校验的原始模型文本不得展示或持久化为可信回答。
- 降级轮次可以持久化以维持上下文，但必须使用 `consume_quota=False` 完成配额
  退款。
- `fact_collection + unverified_guidance` 是唯一新增放行的非正式覆盖安全例外；
  其他非法字段组合仍须拒绝。

## 设计

### 1. DeepSeek 整体时间预算

新增配置 `LLM_TOTAL_TIMEOUT_SECONDS`，默认值和生产值均为 30 秒。现有
`LLM_TIMEOUT_SECONDS` 继续表示单次 HTTP 请求上限，单次请求不得突破整次逻辑
调用的剩余预算。

`DeepSeekProvider._run_provider_call()` 是统一预算边界：

- 所有请求显式使用 `thinking.type=disabled`；咨询任务需要的是受限 JSON
  抽取和短回答，不使用会占满总预算的长推理模式；
- 有 `BoundedExecutor` 时，调用
  `run(..., total_timeout_seconds=30)`；
- 无执行器的测试或独立使用场景，通过异步超时边界执行同一 operation；
- operation 包含首次 HTTP 请求、可重试网络错误、短暂退避以及结构化格式纠正；
- 预算耗尽时取消仍在运行的任务，释放执行器并发槽位；
- 总超时统一转换为可重试的 `provider_timeout`，并记录一次 timeout 健康事件；
- 正常结果到达后立即返回，不等待预算结束。

总预算应用于 `extract_facts()`、`continue_case()` 和 `polish_text()` 的完整公开
调用，不在 `_request()` 的每一次尝试上重新计时。

### 2. 上下文输入

Pipeline 保留现有受限上下文构建方式：

- 当前用户问题完整传入 Provider；
- 最近最多 6 轮有效对话进入会话上下文；
- 用户历史消息和助手历史回复继续受现有字符上限约束；
- 已确认的会话事实、当前 Playbook、历史未核验主题和允许的主题集合继续传入；
- 不把其他用户、其他会话或未声明槽位混入当前请求。

追问仍调用 `continue_case()` 或 `extract_facts()` 的 DeepSeek 实现，不使用仅靠
关键词直接回答的旁路。紧急场景也继续调用 DeepSeek 提取，同时由本地安全规则
控制最终紧急指导。

### 3. Provider 故障统一降级

Pipeline 在消息已规范化、Provider 已确定且会话已建立后，对
`ProviderError` 统一进入本地降级。覆盖：

- `provider_invalid_output`；
- `provider_timeout`；
- `provider_network`；
- `provider_busy`；
- 限流、服务端错误、拒绝和临时不可用；
- 生产配置异常。

降级结果按以下优先级生成：

1. 当前消息命中紧急风险时，返回现有本地紧急指导。
2. 会话已绑定正式 Playbook 时，保留该 Playbook 和已确认事实，询问按 Playbook
   顺序排列且尚未问过的首个缺失关键事实；若缺失项均已问过，再使用更明确的
   类型化确认问题，不原样重复上一条追问。
3. 会话已有未核验主题时，保留历史主题，并使用 `GuidanceBuilder` 对应主题的
   `next_question`。
4. 没有历史主题但当前原文可由本地路由明确识别时，使用该主题的针对性问题。
5. 只有在本地也无法识别时，才询问通用的争议对象、具体行为和当前诉求。

如果正式 Playbook 已没有缺失必填事实，则保留此前已持久化的方案，询问用户希望
继续核对哪个既有步骤或当前诉求；不得猜测用户意图，也不得在 Provider 故障时
生成新的法律判断。

降级轮次使用以下持久化语义：

- `turn_kind="fact_collection"`，紧急风险除外；
- 保留正式覆盖或未核验主题覆盖；
- `provider_request_id=null`，不伪造模型请求标识；
- 审计状态为 `degraded`，错误类别保留实际 Provider 类别；
- `consume_quota=False`，预留额度转为 `refunded`；
- 保留既有 `scenario_id`、facts、followup round 和主题历史；
- 只有既有状态属于 `need_more_facts`、`ready` 或 `escalate` 时才保留；
  新建会话的 `collecting` 或残留 `error` 必须转换为本轮公开结果状态；
- 允许持久化降级问题，保证用户下一次追问仍能联系上下文。

历史列表只投影 `need_more_facts`、`ready` 和 `escalate`。读取列表时跳过仍处于
`collecting` 或 `error` 的内部记录，避免单条未完成记录拖垮整个历史接口；单条
详情及公开记录的响应内容仍执行完整性校验。

### 4. 前端响应契约

`validateTurnCombination()` 与后端 `ConsultResponse` 保持一致。非指导轮次通常只
能包含 `coverage.mode="formal"`，但允许以下唯一例外：

```text
turn_kind = "fact_collection"
coverage.mode = "unverified_guidance"
```

该例外仍须满足事实收集轮次的全部其他约束：

- 不得包含 `plan`、`verdict`、`reply` 或 `guidance`；
- 必须至少包含一个 `questions` 或 `limitations`；
- 不得因放行该例外而跳过 coverage、quota、usage 或其他字段校验。

紧急指导、未核验指导、正式方案、方案更新和短回答的现有约束不变。前端测试应
直接使用后端合法响应样例，防止两边契约再次漂移。

### 5. 浏览器等待保护

仅对 `/api/consult` 和 `/api/trial/consult` 设置 35 秒请求上限，不影响附件上传、
验证码或其他可能具有不同耗时要求的接口。

- 使用 `AbortController` 终止超时请求；
- 无论成功、失败或超时，都清除定时器并退出 `busy.consult`；
- 超时与普通离线错误使用不同错误码和中文提示；
- generation 防护继续丢弃已失效请求的迟到结果；
- 前端不自行减少配额，只采用后端响应中的权威 quota；
- 超时或降级后保留用户继续提问和重试的入口。

后端应在 30 秒 Provider 总预算耗尽后立即构建本地回复，预留约 5 秒用于本地构建、
持久化和网络传输。35 秒是防止页面永久等待的最后保护，不是正常响应目标。

## 数据流

1. 用户提交当前问题，前端进入加载状态并启动 35 秒保护。
2. API 建立或读取当前会话并预留一次配额。
3. Pipeline 组装当前消息、最近对话、已确认事实和当前主题。
4. DeepSeek 在统一 30 秒总预算内执行一次逻辑调用。
5. 合法结果立即通过 Pipeline 和后端响应模型校验后返回。
6. Provider 失败时，Pipeline 使用会话状态和本地规则生成针对性降级回复。
7. 正常 DeepSeek 结果结算额度；降级结果退回额度。
8. 浏览器按与后端一致的契约校验并展示，不再误报完整性错误。

## 错误与配额矩阵

| 情况 | 用户结果 | 配额 | 最长页面加载 |
| --- | --- | --- | --- |
| DeepSeek 正常且结构合法 | 立即展示模型结果 | 正常结算 | 35 秒以内 |
| 首次格式异常、纠正成功 | 展示纠正后的结果 | 正常结算 | 30 秒 Provider 预算内 |
| 格式最终异常 | 展示针对性本地回复 | 退回 | 约 30 秒内返回 |
| 超时、网络错误、限流或繁忙 | 展示针对性本地回复 | 退回 | 约 30 秒内返回 |
| 前端 35 秒仍未收到响应 | 结束转圈并显示超时提示 | 前端不扣减；后端按最终状态结算 | 35 秒 |
| 持久化或基础设施异常 | 显示现有安全错误，不泄露内部信息 | 已预留额度退回 | 不伪造成功回复 |

## 可观测性

- Provider 健康记录只写 Provider、模型、结果类别、耗时和用量。
- Pipeline 审计区分 `invalid_output`、`timeout`、`network`、`busy` 等类别。
- 不记录用户原文、完整上下文、API 密钥或模型提示。
- 前端完整性错误仍保留，用于拦截真正非法的后端响应。
- 发布后通过请求耗时和降级计数确认没有 60 至 90 秒的等待叠加。

## 测试

### 后端契约

- 接受 `fact_collection + unverified_guidance` 安全澄清。
- 继续拒绝其他 `fact_collection + 非 formal` 组合。
- 继续拒绝安全澄清中出现 plan、verdict、reply 或 guidance。
- 验证正常响应、降级响应和配额对象都能通过公开 schema。

### Provider

- 模拟阻塞 HTTP，确认有执行器和无执行器路径都在总预算内超时。
- 模拟网络重试与格式纠正，确认共享同一个预算而不是重新获得 30 秒。
- 超时取消后确认执行器 running 归零，并发槽位可被下一请求使用。
- 正常快速响应不等待剩余预算。
- timeout 健康事件只记录一次。

### Pipeline

- `ProviderOutputError` 返回针对当前主题的问题并退款。
- timeout、network、busy、限流和配置异常均进入本地降级。
- 已有正式会话时保留 Playbook、事实和 followup round。
- 已有未核验主题时保留历史主题，不因通用词误切换纠纷。
- 当前有紧急风险时，Provider 失败仍返回紧急指导。
- 无法识别主题时才使用通用澄清问题。
- 正常 DeepSeek 路径继续消费一次额度，降级路径保持剩余次数不变。

### 浏览器端到端

- 注入 `ProviderOutputError` 后匿名试用能看到针对性回复。
- 页面不再显示“服务返回的数据未通过完整性检查”。
- 匿名试用剩余次数仍为 5。
- 模拟 Provider 超时后，页面在 35 秒内结束加载状态。
- 模拟真正非法组合时，前端仍显示完整性错误。
- 正常 DeepSeek 首问和上下文追问均显示与当前问题相关的结果。
- 在桌面视口和 `360x800` 手机视口检查加载、回复、错误和再次提问状态。

### 回归

- 运行相关单元、API、Pipeline、Provider、配额和 E2E 测试。
- 运行全量测试、Python 编译检查和 `git diff --check`。
- 使用浏览器验证本地真实 DeepSeek 路径，确认当前问题和历史上下文均被使用。

## 发布与验收

1. 本地测试全部通过后重启本地服务，验证匿名试用和登录追问。
2. 构建不可变镜像 `weiquan-agent:2026.08.15-2`。
3. 运行现有生产预检和部署流程，只重建并重启 `weiquan-app`。
4. 不重启、不重建、不迁移 `weiquan-postgres`。
5. 检查 `/live`、`/ready`、内部指标、应用容器健康和公网 HTTPS。
6. 用不含个人敏感信息的对话验证首问、上下文追问和一次受控降级。
7. 核对线上应用镜像标签、静态文件哈希、响应耗时和配额最终状态。

验收成功必须同时满足：

- 正常 DeepSeek 回答与当前问题及最近上下文相关；
- Provider 异常时用户仍能看到针对当前纠纷的安全回复；
- 合法安全澄清不再触发前端完整性错误；
- 降级回复不减少试用或注册额度；
- 页面加载状态不超过 35 秒；
- PostgreSQL 和独立音频项目未被重启、重建或修改。
