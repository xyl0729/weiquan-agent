# 阿里云厂商凭据校验修复设计

## 背景

生产清理任务在构建删除服务时报告 `ALIYUN_ACCESS_KEY_ID 未配置`，但受控环境、
运行容器和 Compose 临时容器均已确认相关变量存在。根因是删除服务复用了内部
加密密钥读取函数 `_required_secret()`；该函数要求值至少为 32 字节，而合法的
阿里云 AccessKey ID 不保证达到这一长度。

会话密钥和 IP HMAC 密钥依赖至少 32 字节的安全要求，该要求不能放宽。

## 方案

在 `app/deps.py` 增加独立的厂商凭据读取函数。它只接受 Secret 类型中存在且
非空的字符串，不施加内部加密密钥的长度规则。`build_deletion_service()` 使用
该函数读取阿里云 AccessKey ID 和 AccessKey Secret；会话密钥与 IP HMAC 密钥
继续使用 `_required_secret()`。

本次不修改凭据值、不记录凭据、不改变 OSS、数据库、备份、网络或定时任务配置。

## 测试与发布

回归测试覆盖：

- 合法但短于 32 字节的阿里云凭据可以构建删除服务；
- 缺失或空的阿里云凭据仍然被拒绝；
- 少于 32 字节的内部密钥仍然被拒绝。

聚焦测试和全量测试通过后，构建固定版本
`weiquan-agent:2026.08.12-1` 并部署为新 release。部署不得删除或重建正式
PostgreSQL 数据卷，且备案通过前继续只监听 `127.0.0.1:8001`。

部署后手工运行清理服务，确认成功后启用清理与备份定时器；监控定时器继续禁用。
最后核对加密备份和校验和对象均存在于私有 OSS，并检查应用健康、数据库迁移、
正式数据卷和监听端口。
