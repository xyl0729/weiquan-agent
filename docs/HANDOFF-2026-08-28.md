## 已探明的官方接口(补法条时用)

全国人大数据库前端是 SPA,`/detail?id=...` 只返回外壳。真实接口:

```
GET https://flk.npc.gov.cn/law-search/search/flfgDetails?bbbs=<ID>
Headers: User-Agent: Mozilla/5.0
         Referer: https://flk.npc.gov.cn/detail?id=<ID>
```

注意参数名是 **`bbbs`** 而不是 `id`,值就是详情页 URL 里的那个 id。民法典返回 217KB,含 `title`/`sxrq`(施行日期)/`gbrq`(公布日期)/`sxx`(时效性)。

民法典的 id:`ff808081729d1efe01729d50b5c500bf`
其余法规的 id 见 `docs/legal-data-verification-checklist.md` 的官方来源表。

**未验证的部分**:`sxx: 3` 这个字段我没查证它代表「有效」还是别的含义。如果你依赖时效性判断,先自己确认这个枚举。

### 法条召回改主题推断

**原方案被数据否掉**。我最初加了 BM25 分数阈值 12.0,假设噪声条文分数低。实测正好相反:

- 甲醛案中方向相反的第七百一十一条(承租人损坏租赁物、出租人可解约)= **50.19 分**
- 对用户有利的第七百一十三条 = **25.46 分**
- 被狗咬案中无关的相邻关系条文 = 66.95,正确的动物致害 = 75.89

任何能挡住高分噪声的阈值都会连正确条文一起挡掉。**BM25 只算字面重叠,判不出条文站在争议的哪一边**。

改为 `app/retrieval/expansion.py` 的 `infer_topic()`:触发词只回答「这是哪类纠纷」,条文仍由人工精选的 `GENERAL_BASIS_REFS` 决定。

修了两处优先级(顺序即优先级,先匹配到的胜出):

- `personal_injury` 提到 `property_neighbor` 之前——「被邻居家的狗咬」是人身损害,不是相邻关系
- 租赁关系词要在场所现象词之前——「房东不给修漏水」是租赁维修义务,不是邻里纠纷

### 动作证据结构化校验

原来 `issubset` 让动作只能整条保留或删除,模型无法按案情改写——这是模板腔的直接来源:不论用户说甲醛还是欠薪,动作和证据都是逐字相同的句子。
