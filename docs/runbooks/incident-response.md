# 生产事件响应手册

本手册适用于维权咨询站点。处置目标依次为：阻止跨用户或数据扩大、保留登录和删除
能力、保护备份与删除语义、恢复服务。不要在工单、聊天或日志中记录咨询正文、模型
输出、附件文字、文件名、邮箱、Cookie、Authorization、验证码、token、密钥或路径。

## 首次响应

1. 记录 UTC 与北京时间、告警类别、版本镜像、请求 ID 和无内容错误类别。
2. 若风险涉及所有权、配额、存储、数据库或资源耗尽，立即设置
   `NEW_WORK_ENABLED=false`，按部署手册重启应用并确认返回 `new_work_paused`。
3. 若风险涉及公开注册，将 `ROLLOUT_STAGE=internal` 且
   `PUBLIC_LAUNCH_APPROVED=false`。
4. 检查 `/live`、`/ready`、内部指标、Nginx 5xx、容器重启、磁盘、swap、
   PostgreSQL、Provider、邮件、OCR 队列、备份和临时附件年龄；CAPTCHA 只在
   `CAPTCHA_ENABLED=true` 时检查。

人工暂停后必须继续允许登录、退出、历史读取、咨询删除以及附件读取、确认和删除。
若这些操作也失败，按高优先级可用性事件处理。

## 严重级别

- P0：确认或疑似跨用户读取/修改、删除语义失效、秘密泄露、备份恢复错误。
- P1：配额超发、PostgreSQL 不稳定、持续 OOM/swap、反复重启、磁盘达到 80%、
  备份失败或站点不可用。
- P2：DeepSeek、DirectMail、OSS、OCR 或已启用的 CAPTCHA 单项退化，但数据边界
  保持正确。

P0 立即暂停新工作和扩量，保留现场并禁止公开恢复。P1 先暂停新工作，再恢复容量或
回滚。P2 使用既有失败状态和重试边界；验证码启用时不得临时绕过，配额、隐私和
内容隔离始终不得绕过。

## 分类处置

### 所有权或认证

停止新工作和公开注册，吊销受影响会话，保留仅含请求 ID、身份摘要、路由、状态和
时间的证据。使用两个独立账号复现读取、续问、确认和删除边界。任何跨用户结果都按
P0 处理，在修复、全量隔离测试和用户明确批准前不得恢复。

### PostgreSQL

暂停新工作，确认容器健康、连接数、磁盘与最近备份。禁止在生产直接执行破坏性 SQL。
需要回滚镜像时使用固定的 previous image；迁移不自动降级。数据库损坏或不可读时按
`backup-and-restore.md` 在隔离环境恢复、校验迁移与关键表、重放删除清单并执行
30 天清理，验证完成后才恢复写入。

### 磁盘或资源

磁盘达到 80%、持续 swap、OOM 或反复重启时保持 `NEW_WORK_ENABLED=false`。检查
附件临时文件年龄、日志轮换、备份暂存和 PostgreSQL 卷，不手工删除未知文件。先运行
有界清理和既定保留策略，再验证两个并发咨询加一个 OCR。资源稳定前不扩大用户数。

### DeepSeek 或队列

保持 Fake 仅用于离线测试，生产不得切换 Fake。确认 429、5xx、非法响应、超时和队列
已满分别映射为安全错误，失败预留已幂等退还。不要在故障期间循环真实调用。恢复后
只在用户明确批准下执行一次最小真实冒烟。

### 邮件、CAPTCHA 或 OSS

邮件失败保留待验证账号并允许受限重发；不得手工跳过邮箱验证。仅当
`CAPTCHA_ENABLED=true` 时，CAPTCHA 失败才关闭注册和首次匿名领取，且不得伪装
成功；关闭状态不依赖该服务。OSS 加密或上传失败时不得宣称删除完成；保留无内容
outbox，恢复私有上传后继续处理。

### OCR 或附件

OCR 超时、取消、非法输出或进程崩溃必须清理源文件、作业文件和结果文件，并把处理中
记录安全地转为失败。不得把原文件或未确认 OCR 文字移入静态目录。OCR 不可用时仍可
保留纯文字咨询，除非人工总开关已关闭。

## 恢复门禁

恢复 `NEW_WORK_ENABLED=true` 前必须确认根因和修复版本、全量测试与故障矩阵、数据
隔离、配额、备份、删除重放、磁盘低于 80%、无持续 swap/OOM、容器稳定、公网 HTTPS
健康。恢复公开注册还必须重新满足 `public-beta-rollout.md` 的阶段门槛，并取得用户
明确批准。事件结束后只保存脱敏时间线、根因、修复和验证证据。
